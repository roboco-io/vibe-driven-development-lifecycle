# PRD: 라이프사이클 상세 다이어그램 — 순환 링 뷰

> **문서 목적**: 사이트의 P1~P6 라이프사이클 mermaid 다이어그램을, 단계별 수행 주체(인간/AI)와
> 하네스(인간 관문 + 자동 가드레일)를 표현하는 상세 순환 다이어그램으로 교체하기 위한 PRD.
> 심층인터뷰(2026-07-25)와 브라우저 프로토타입 큐레이션으로 요구사항을 확정했다.
> 프로토타입: `.superpowers/brainstorm/10022-1784977617/content/pipeline-v2-ring.html` (승자),
> `pipeline-v1.html`·`layout.html` (탈락안 — 결정기록은 8장).

## 1. Problem

현재 P1~P6 다이어그램은 단계 이름과 순서만 보여준다. "각 단계에서 누가 무엇을 하는가"와
"무엇이 그 단계를 지키는가(하네스)"는 본문을 읽어야만 알 수 있다. VDLC의 차별점이
주도권 구분과 관문·가드레일 구조에 있으므로, 다이어그램이 이를 첫인상에서 전달해야 한다.

baseline: 방문자는 단순 순환도를 보고 "일반적인 개발 사이클"로 오독한다.

## 2. 확정된 요구사항 (인터뷰 결정사항)

| # | 질문 | 결정 |
|---|---|---|
| 1 | 용도 | 기존 P1~P6 **대체** (병행·단독 자산 아님) |
| 2 | 하네스 범위 | **인간 관문 3개 + 단계별 자동 가드레일** (컨텍스트 자산 흐름은 제외) |
| 3 | 주체 입도 | **인간/AI 2주체 + 주도·보조 구분** (역할·직군 세분 안 함) |
| 4 | 레이아웃 | **순환 링 + 단계 카드** — 파이프라인 컬럼의 정보 구성을 링에 재배치 (프로토타입 A/B/C → 파이프라인 → 링 순으로 큐레이션) |
| 5 | 구현 방식 | **Vue 컴포넌트 1벌 + 로케일 문자열 데이터** (정적 SVG 3벌·PNG 탈락) |
| 6 | 적용 범위 | **매니페스토 + 랜딩 × 3로케일 (6곳)**. 슬라이드는 추후 과제, vdlc.md는 mermaid 단순판 유지 |
| 7 | 모바일 | 좁은 화면(<960px)에서 **1→6 세로 카드 스택으로 리플로우** |

## 3. 다이어그램 사양

### 3.1 구조 (승자 프로토타입 기준)

- **링 배치**: 시계 방향 — 1 의도 정의(상단) → 2 컨텍스트 설계 → 3 공동 구현 → 4 검증(하단) → 5 배포와 관찰 → 6 환류 → 1. 인접 단계는 링 호(弧) 화살표로 연결.
- **단계 카드** (6장): 제목 행(번호+이름, 주도권 배지) / 👤 인간 작업 / 🤖 AI 작업 / 🛡 가드레일 스트립(구분선 위). 주도 주체의 작업 행이 먼저 온다(3·4·5는 🤖 먼저).
- **주도권 색상**: 인간 주도(1·2·6) = 호박색 계열, AI 주도(3·4·5) = 파란색 계열. 카드 테두리·배지에 적용.
- **관문 배지** (링 위, ◆): 2→3 구간 "계획 승인", 4→5 구간 "최종 리뷰 → 배포 승인".
- **피드백 점선**: 빨강 4→3 "불합격 반송", 보라 6→2 "컨텍스트 자산 갱신"(중앙 관통 곡선).
- **중앙 허브**: "VDLC" + 핵심 명제("의도가 1차 산출물, 코드는 재생성 가능한 2차 산출물").
- **범례**: 인간 주도 / AI 주도 / ◆ 인간 관문 / 🛡 자동 가드레일 / 점선 2종.

### 3.2 카드 콘텐츠 (매니페스토 4장과 1:1 정합 — 이 표가 단일 원천)

| 단계 | 주도 | 👤 인간 | 🤖 AI | 🛡 가드레일 |
|---|---|---|---|---|
| 1 의도 정의 | 인간 | 문제 합의 · PR-FAQ/6-pager · 성공 기준 명시 | 리서치 · 초안 · 모호성 지적 | 의도 문서 템플릿 · 검증 가능한 성공 기준 |
| 2 컨텍스트 설계 | 인간 | 규칙·컨벤션 정비 · ADR·용어집 갱신 | 낡은 자산 탐지 · 골격 초안 | CLAUDE.md · ADR · No-Gos |
| 3 공동 구현 | AI | 계획 요약 되묻기 · 방향 통제 | 계획 제안 → 구현 · 자가 점검 · 병렬 오케스트레이션 | 검증 가능한 작업 단위 · CLAUDE.md 규칙 |
| 4 검증 | AI | 최종 리뷰 · "설명할 수 있는가" 이해 검증 | 자동 테스트 · 정적 분석 · 교차 리뷰 | 리스크 비례 검증 강도 · 1회 통과율 측정 |
| 5 배포와 관찰 | AI | 배포 승인 | 자동 배포 · 운영 관찰 · 이슈의 재현 컨텍스트화 | CI/CD · 관측(로그·에러율·지연) · 롤백 |
| 6 환류 | 인간 | 배운 것 → 규칙·체크리스트 · 이해 부채 상환(학습) | 반복 패턴 추출 · 위키 정리 | 체크리스트 갱신 · 자산 증가량 측정 |

en/ja 번역은 기존 매니페스토 번역 용어를 재사용한다(새 용어 창작 금지).

### 3.3 반응형·테마

- **≥960px**: 링 레이아웃(폭 약 1000~1100px, 컨테이너 내 중앙 정렬, 초과 시 overflow-x).
- **<960px**: 세로 스택 — 카드 1→6 순서, 카드 사이에 관문·반송·자산 갱신을 배지/화살표로 삽입.
- **다크·라이트**: VitePress CSS 변수(`--vp-c-*`) 기반으로 두 테마 모두 가독 확보. 프로토타입은 다크 기준이므로 라이트 팔레트를 파생한다.

## 4. 구현 방법론 (How)

새로 만들지 않고 기존 스택을 활용한다.

1. **컴포넌트**: `docs/.vitepress/theme/` 디렉토리를 신설(현재 기본 테마 — `index.ts`에서 기본 테마 확장 + 컴포넌트 전역 등록은 VitePress 표준 절차)하고 `LifecycleDiagram.vue` 1벌 작성. 링 호·점선은 인라인 SVG, 카드는 HTML/CSS(승자 프로토타입 HTML을 이식 원본으로 사용).
2. **로케일 데이터**: 3.2 표를 `lifecycle-data.ts`의 en/ko/ja 객체로 정의. 컴포넌트는 `useData().lang`으로 로케일 자동 선택 — 페이지에서는 `<LifecycleDiagram />` 한 줄.
3. **교체 지점(6곳)**: `docs/{,ko/,ja/}manifesto.md`의 4장 mermaid 블록, `docs/{,ko/,ja/}index.md`의 랜딩 mermaid 블록.
4. **유지 지점**: `vdlc.md`(GitHub 렌더)와 `slides/slides.md`의 mermaid 단순판, 주간 사이클 다이어그램(`cycle.md`)은 이번 범위 밖. CLAUDE.md의 "mermaid 노드 ID P1~P6 공유" 규칙은 사이트 교체 후 vdlc.md·슬라이드 한정으로 갱신 필요.

## 8. 결정기록 (프로토타입 큐레이션)

- **라운드 목적**: 주체·하네스를 담는 상세 다이어그램의 레이아웃 결정
- **패턴**: 발산형 (병렬 큐레이션, 브라우저 컴패니언)
- **시도한 접근**: A 스윔레인 3레인 / B 단계 카드 세로 스택 / C 순환 링+중앙 허브 (`layout.html`) → 사용자가 CI/CD 파이프라인 레퍼런스 이미지 제시 → 파이프라인 컬럼판 (`pipeline-v1.html`) → 순환 링판 (`pipeline-v2-ring.html`)
- **승자와 선정 근거**: 순환 링판 — 파이프라인의 정보 구성(주체 2층+가드레일 스트립+관문)을 유지하면서 VDLC의 순환 정체성을 보존
- **탈락 사유**: 스윔레인(유지보수 비용·mermaid 불가), 세로 스택 단독(사이클 정체성 약함 — 모바일 뷰로 흡수), 파이프라인 컬럼(선형 인상이 순환 명제와 충돌)
- **핏치 반영 사항**: 3.1 구조 사양 전체가 승자 프로토타입에서 도출됨
